MIMO Communication Analysis Toolkit - Help

This document explains the toolkit architecture, MIMO channel model, the method used to compute MIMO OFDM channel capacity, the meaning of each user input, and how to interpret every output plot and file.

1) Toolkit Architecture

  • Input Channel Model: The toolkit streams a frequency-domain channel from either an RST/RSP archive or a live STK/RFCM project. Each coefficient is the complex port-to-port transmission response from one transmit antenna element to one receive antenna element.
  • Live RFCM Mode: STK Engine loads a VDF/SC project, discovers valid RFCM analysis configurations and links, and returns each frequency-pulse response directly in memory without an intermediate HDF5 archive.
  • Antenna Usage: Every transmit antenna and every receive antenna reported for the selected link is used. There is no per-antenna selection; the full MIMO array is analyzed as a single spatial channel matrix.
  • OFDM Waveform Assumption: The link is analyzed as an OFDM waveform using a user-selected 3GPP subcarrier spacing (SCS) and resource-block count. The imported frequency sweep is band-limited resampled onto the exact OFDM subcarrier center frequencies.
  • Capacity Engine: For every OFDM subcarrier, the complex channel matrix is assembled and its equal-power Shannon capacity is computed. Subcarrier capacities are summed across the occupied bandwidth to produce total capacity for that time sample.
  • Channel Diagnostics: Alongside capacity, each sounding also yields its spatial eigenvalue spectrum, per-stream capacities, RMS delay spread, coherence bandwidth, and the temporal correlation against the previous sounding.
  • Time and Sounding History: Every scenario frame and every channel sounding within that frame is treated as a distinct, chronologically ordered time sample (frame-major, sounding-minor), so capacity is reported as a full time history rather than a single value.
  • Streaming for Large Files: The HDF5 response dataset is read one sounding and one antenna-port path at a time and resampled immediately onto the OFDM grid. The full response array is never loaded into memory, which allows multi-gigabyte channel files to be processed safely.
  • Optional GPU Acceleration: When Use GPU is selected, the batched capacity and eigenvalue operations run on a local NVIDIA GPU through CuPy instead of NumPy. Channel reading, resampling, and the delay/Doppler metrics always run on the host.

2) What Is MIMO?

MIMO (Multiple-Input, Multiple-Output) refers to a radio link that uses multiple antenna elements at both the transmitter and the receiver. Instead of a single scalar channel gain between one Tx and one Rx antenna, the link is described by a complex channel matrix that captures every antenna-to-antenna coupling simultaneously:

H(f) ∈ ℂNr × Nt,   where Nt is the number of transmit antenna ports and Nr is the number of receive antenna ports.

Each entry Hi,j(f) is the complex transmission coefficient from transmit port j to receive port i at frequency f, exactly as reported by the imported S-parameter sweep. When the propagation environment provides enough multipath richness and angular diversity, this matrix supports multiple independent spatial data streams at the same time, on the same frequency and time resource — this is spatial multiplexing, the core benefit of MIMO.

How much benefit is available depends on the channel's spatial structure: a channel dominated by a single strong path (for example, pure line-of-sight with little scattering) behaves close to rank-1 and offers little multiplexing gain, while a rich multipath channel (common in complex urban and indoor environments, including many non-line-of-sight conditions) can offer multiple usable spatial modes.

3) Method Used to Compute MIMO OFDM Channel Capacity

  1. Channel matrix per subcarrier: For every active OFDM subcarrier frequency, the imported frequency sweep is resampled onto that exact subcarrier frequency, for every Tx–Rx antenna pair, producing Hk for subcarrier k. The resampling is band-limited: the imported channel frequency response is transformed to the delay domain with an inverse DFT and then evaluated back at the requested subcarrier frequencies. This preserves the channel's multipath delay structure, which component-wise linear interpolation of the real and imaginary parts would smear.
  2. Equal-power allocation: The user-specified total transmit power is divided equally across every active subcarrier and, on each subcarrier, equally across every transmit antenna port. This mirrors a realistic scheduler baseline rather than an idealized water-filling allocation.
  3. Per-subcarrier capacity: Using the Shannon/Telatar MIMO capacity expression,

    Ck = log2 det( I + γk Hk HkH )  (bits/s/Hz)

    where γk combines the per-port transmit power, the number of transmit ports, and the thermal noise power (from noise density and noise figure) on that subcarrier. The determinant is evaluated with a numerically stable log-determinant (slogdet) rather than an explicit eigenvalue product.
  4. Total capacity for one time sample:

    C = Δf ∑k Ck  (bits/s)

    where Δf is the selected subcarrier spacing and the sum runs over every active subcarrier in the configured resource-block allocation.
  5. Batched, memory-bounded evaluation: Subcarriers are processed in fixed-size batches so that only a small Gram matrix set is held in memory at any time, using whichever of H HH or HH H is smaller (an 8×32 uplink, for example, always forms the 8×8 Gram matrix rather than 32×32).
  6. Spatial diagnostics per subcarrier: The eigenvalues of the smaller Gram matrix are also used to compute the eigenvalue spectrum, per-stream capacity, effective rank, condition number, and dominant eigenvalue fraction described in Section 8, and these are averaged across all active subcarriers for that time sample.
  7. Per-stream capacity: Because det(I + γ G) = ∏i (1 + γ λi), the total capacity decomposes exactly into one term per spatial eigenmode, Ci = Δf ∑k log2(1 + γk λi,k). These per-stream capacities always sum to the reported total capacity.
  8. Delay and Doppler metrics: The resampled channel is transformed to the delay domain to form a port-averaged power delay profile, from which the RMS delay spread and coherence bandwidth are derived. The channel matrix is also correlated against the previous sounding to obtain the temporal correlation and the implied coherence time.
  9. Repeat over time: Steps 1–8 are repeated for every scenario frame and every channel sounding inside that frame, in chronological order, to build the full capacity and channel-diagnostic time history.
Note: Because the imported S-parameters are treated as already including antenna gain and coupling effects from the input port of each transmit antenna to the output port of each receive antenna, no separate antenna-pattern or path-loss correction is applied. Capacity is computed directly at the RF reference ports represented in the imported file.

4) RST / RSP File Format (Channel Import)

The toolkit expects HDF5-based channel files with a /Links hierarchy, the same format used by the End to End Communication Analysis toolkit. After clicking Load Metadata, every link in the file is discovered and its Tx/Rx antenna counts, sounding count, sample count, sounding interval, bandwidth, and center frequency are displayed.

  • /Links/<Link>/Transmitter - Tx antenna metadata (antenna count and, when available, antenna names)
  • /Links/<Link>/Receiver - Rx antenna metadata (antenna count and, when available, antenna names)
  • /Links/<Link>/Waveform - bandwidth, center frequency, sample count, channel sounding count, sounding interval
  • /Links/<Link>/Channel Characterization/Response - frequency response for every Tx-Rx-sounding combination (real/imaginary interleaved)
  • /Links/<Link>/Channel Characterization/Time Array - frame time axis
Frame and sounding ordering: Each scenario frame may contain multiple channel soundings, taken at contiguous time steps within that frame. The toolkit processes every sounding of every frame, in order, and assigns each one a timestamp equal to the frame time plus sounding_index × Sounding Interval.
Large files: The full response dataset is never loaded into memory at once. If the file cannot be opened at all and the error mentions a truncated file or a stored end-of-file mismatch, the file itself is incomplete (for example, the simulation ran out of disk space while writing) and must be regenerated; this is not a toolkit memory limitation.

Live STK / RFCM Project Mode

Select STK/RFCM Project (VDF/SC), browse to the project, and click Load Metadata. The RFCM Analysis list appears immediately before Link. Selecting an analysis automatically reconstructs and repopulates its links. Every Tx/Rx antenna coupling and sounding returned by the selected link is passed into the same OFDM capacity pipeline used for archive data.

This mode requires STK 13.1, STK Engine and RF Channel Modeler licenses, and the bundled agi_stk13 Python wheel. RFCM runs in an isolated broker process to satisfy STK's one-Engine-instance-per-Python-process restriction. A bounded two-frame buffer lets RFCM compute upcoming frames while the toolkit post-processes the current frame; generation pauses only when the buffer is full. Stopping the worker terminates the constructed RFCM analysis during cleanup.

5) User Inputs - Technical Meaning and Theory

InputTechnical MeaningTheory / Practical Impact
LinkSelects which link from the imported RST/RSP file to analyze.Populated after Load Metadata. Every transmit and receive antenna reported for the selected link is used automatically; no per-antenna coupling is chosen.
Subcarrier Spacing (SCS)OFDM subcarrier frequency spacing, offered at the standard 3GPP NR values (15, 30, 60, 120, 240, 480, and 960 kHz).Sets Δf in the capacity summation. For a fixed occupied bandwidth and fixed transmit power spectral density, ideal Shannon capacity is largely insensitive to SCS; SCS mainly changes how many subcarriers span the same bandwidth and how finely the frequency-selective channel is sampled.
Resource BlocksNumber of 3GPP NR resource blocks used. Each resource block contains 12 subcarriers.Together with SCS this sets the occupied OFDM bandwidth (12 × Resource Blocks × SCS), which must not exceed the bandwidth of the imported channel file.
Total Tx PowerTotal radiated power across the entire transmit array, in dBm.Divided equally across every active subcarrier and, on each subcarrier, equally across every transmit antenna port. Higher power raises the per-subcarrier SNR and therefore capacity, with diminishing (logarithmic) returns.
Thermal Noise DensityReceiver noise power spectral density in dBm/Hz (a value near -174 dBm/Hz corresponds to standard room-temperature thermal noise).Combined with subcarrier spacing and noise figure to obtain the thermal noise power on each subcarrier at each receive port.
Receiver Noise FigureAdditional receiver noise contribution, in dB, on top of the thermal noise floor.Higher noise figure directly reduces per-subcarrier SNR and therefore reduces capacity; it does not change the channel's spatial structure (rank, condition number, dominant eigenvalue fraction).
Acceleration (Use CPU / Use GPU)Selects whether batched matrix operations run on the CPU with NumPy or on a local NVIDIA GPU with CuPy.Both paths compute the identical mathematical result. GPU mode requires the CuPy package matching the installed CUDA version and a CUDA-capable GPU; it is most beneficial for large antenna counts, wide bandwidths, or long scenario time histories.

6) Optional Plots

The Optional Plots group on the left panel controls which diagnostic panels are added to the Capacity Time History output. All four are enabled by default. The capacity, eigenvalue spectrum, condition number, and dominant eigenvalue fraction panels are always produced. Toggles are read when the plots are rendered, so changing them requires re-running the analysis.

7) Capacity Summary (Status and KPI Tab)

  • Mean Capacity: Average of the total OFDM capacity (C(t), converted to Gbps) across every processed time sample in the scenario.
  • Peak Capacity: The single highest instantaneous capacity observed across the scenario time history, typically corresponding to a time sample with strong, well-conditioned multipath coupling.
  • Mean Spectral Efficiency: Average, across time, of the per-subcarrier spectral efficiency (bits/s/Hz per subcarrier) averaged over the OFDM band. Multiplying this by the occupied bandwidth reproduces the total capacity.
  • Mean Effective Rank: Average, across time, of the entropy-based effective rank described in Section 8. This indicates how many spatial modes are typically usable, not merely how many are mathematically nonzero.

8) Output Plots and Files (Capacity Time History Tab)

After analysis completes, the selected time-history plots are stacked into a single scrollable view on the Capacity Time History tab, scaled to the tab width so each panel stays readable. Every panel is also saved individually as a PNG file in the local output/ folder, named mimo_<metric>_<link>.png. A companion CSV file, mimo_capacity_<link>.csv, records every time sample with its frame index, sounding index, and all scalar metrics below.

Every plot title carries a second line naming the link as <Transmitter> to <Receiver>, read from the node names in the imported file (falling back to the raw link name if the file carries none).

On-screen versus exported colors: The in-application plots use a bright, high-contrast palette chosen to stay legible on the toolkit's dark background. The exported PNG files are rendered separately on a white background with a deeper palette, so they drop directly into reports and slides. The underlying data is identical.
Plot / ColumnWhat It RepresentsHow to Interpret
Capacity (capacity_bps) Total instantaneous OFDM channel capacity at that time sample, computed as described in Section 3. Higher values indicate a stronger, better-conditioned MIMO channel at the configured Tx power, noise figure, and OFDM bandwidth. Drops often align with reduced dominant eigenvalue fraction or lower effective rank, but can also simply reflect lower received signal power. The y-axis always starts at zero so that relative variation is not visually exaggerated.
Eigenvalue Spectrum and Effective Rank Every eigenvalue of the channel Gram matrix, in dB, plotted as its own colored curve against scenario time, with the entropy-based effective rank reff = exp( -∑i pi ln pi ) overlaid as a thicker red curve on a separate right-hand axis. Here pi = λi / ∑j λj, and all values are averaged over the active subcarriers. The eigenvalue curves show both the absolute strength of each spatial mode and the spread between them; a wide vertical gap between the top and bottom curves means the weaker modes are not usable. Effective rank condenses that spread into a single number: near min(Nt, Nr) means energy is spread across many comparable modes, near 1 means one mode dominates. Effective rank is scale-invariant, so several equally weak modes still report a high value — read it together with the eigenvalue levels and the capacity plot, not in isolation.
Per-Stream Capacity (optional) The capacity carried by each spatial eigenmode, strongest first, in Gbps. The curves sum exactly to the total capacity. A cumulative reading tells you what a receiver limited to one, two, or three streams would achieve, which directly informs how many RF chains the radio needs. Streams that hug zero throughout the scenario are contributing nothing and represent hardware that could be removed.
Capacity CDF (optional) Empirical cumulative distribution of total capacity over every processed sounding, with dashed markers at the 10% and 50% outage points. Read the 10% marker as the capacity the link meets or exceeds 90% of the time — this is normally the number a link budget should be built on. A steep curve means a stable link; a long lower tail means occasional deep fades that a fixed-rate service would not survive without margin.
Condition Number (condition_number) Ratio of the largest to the smallest singular value of the channel matrix (via the square root of the largest-to-smallest Gram-matrix eigenvalue ratio), averaged over all active subcarriers. A condition number near 1 indicates a well-balanced, orthogonal-like channel that is favorable for spatial multiplexing. A large condition number indicates that one or more spatial modes are much weaker than the strongest mode, which limits achievable multiplexing gain even if the channel is not fully rank-deficient. This plot uses a logarithmic y-axis when all values are positive because condition number can span several orders of magnitude, and a dashed reference line at 1 (the ideal, fully orthogonal channel) is always kept visible for scale.
Dominant Eigenvalue Fraction (dominant_eigenvalue_fraction) pmax = λmax / ∑i λi, the fraction of total channel energy carried by the single strongest spatial eigenmode, averaged over all active subcarriers. Values close to 1 mean the link is effectively behaving like a single dominant path (for example, a strong line-of-sight or a single strong specular reflection), so most capacity gain would need to come from a higher-order modulation or more power rather than spatial multiplexing. Lower values indicate that channel energy is shared among multiple modes, which is favorable for MIMO spatial multiplexing.
RMS Delay Spread and Coherence Bandwidth (optional)
(rms_delay_spread_s, coherence_bandwidth_hz)		 The second central moment of the port-averaged power delay profile, στ, and the coherence bandwidth it implies under the usual flat-fading rule of thumb, Bc ≈ 1 / (5 στ). A dashed reference line marks the configured subcarrier spacing. Each subcarrier only experiences flat fading if the coherence bandwidth comfortably exceeds the subcarrier spacing. When the coherence bandwidth curve approaches or falls below the dashed reference line, the numerology is too coarse for the channel's delay dispersion and a wider subcarrier spacing is warranted. Delay spread also bounds the required cyclic prefix: a CP shorter than the channel's delay extent causes inter-symbol interference that this capacity model does not represent.
Temporal Correlation and Coherence Time (optional)
(adjacent_sounding_correlation, coherence_time_s)		 The normalized magnitude correlation between the channel matrix of this sounding and the previous one, and the coherence time implied by fitting an exponential decay to that single lag, Tc = -Δt / ln ρ. Coherence time is drawn on a logarithmic right-hand axis. Low correlation or short coherence time indicates fast channel variation, which demands more frequent CSI feedback, denser pilots, and faster precoder updates; stale channel knowledge in such conditions causes real throughput to fall well below the capacity shown here. The first sounding has no predecessor, so both values are blank at the start of the scenario. Note that the shortest resolvable coherence time is set by the sounding interval in the imported file.
time_s, frame_index, sounding_index The chronological timestamp of the sample, and the originating scenario frame and channel sounding within that frame. Use these to correlate a capacity dip or rank change with a specific point in the movement scenario, or to re-inspect the corresponding channel frequency/delay behavior in the End to End Communication Analysis toolkit.
Non-line-of-sight behavior: A blocked or non-line-of-sight time sample does not automatically produce a low effective rank. Rich multipath from reflection and diffraction can create several spatial modes of comparable strength, sometimes yielding higher effective rank than a strong single-path line-of-sight condition — while typically also producing lower absolute capacity due to reduced received power. Always review capacity, effective rank, condition number, and dominant eigenvalue fraction together for a complete picture of channel behavior at any given time sample.

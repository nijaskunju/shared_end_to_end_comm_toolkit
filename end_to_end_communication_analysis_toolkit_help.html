End to End Communication Analysis Toolkit - Help

This document explains signal-flow architecture, RST/RSP file interpretation, and theory behind each technical input so users can understand and learn the workflow.

1) Toolkit Architecture

  • Input Channel Model: Imported frequency response H(f) from RST/RSP is converted to an impulse response h(t) through IFFT-based FIR extraction.
  • Transmit Chain: Bits -> Gray-coded M-QAM mapping -> RRC pulse shaping -> oversampled baseband -> RF upconversion at configured center frequency (or active hopping frequency).
  • Propagation/Channel: RF waveform is convolved with h(t), representing the selected Tx-Rx coupling path from the imported file.
  • Noise Model: Either direct SNR-mode AWGN or Tx power + broadband Rx noise mode with power-consistent noise injection.
  • Receiver Chain: Channel estimation + deconvolution, timing alignment, RF downconversion, matched filtering, symbol recovery, hard demapping, BER/EVM/SNR extraction.
  • Per-frame Analytics: Frequency response, delay profile, RX RF spectrum, and constellation panels are generated and exported as animated GIF.

2) Signal Processing Flow (Detailed)

  1. H(f) extraction: For each frame, the selected Tx-Rx response vector is read from channel file.
  2. FIR synthesis: A finite impulse response is derived from H(f) to obtain time-domain channel memory.
  3. QAM generation: Random bits are mapped to QAM symbols with Gray coding to reduce bit-error sensitivity for nearest-neighbor symbol errors.
  4. Pulse shaping: RRC filtering controls inter-symbol interference and spectral occupancy.
  5. Upconversion: Baseband symbols are shifted to RF using configured carrier frequency, or per-frame hopping carrier when hopping is enabled.
  6. Channel convolution: RF transmit sequence is filtered by h(t), producing received RF signal.
  7. Noise injection:
    • SNR mode: AWGN level is set by user SNR.
    • Power/Noise mode: transmit power scaling and broadband Rx-noise-based AWGN are applied.
  8. Channel estimation and equalization: Pilot-assisted LS/Wiener estimate is used for deconvolution/equalization.
  9. Synchronization: Cross-correlation aligns the recovered sequence to transmitted timing.
  10. Downconversion + matched filtering: RF is shifted back to baseband and filtered with RRC before symbol sampling.
  11. Decision and KPIs: Symbols are demapped to bits and BER, theory BER, Peak SNR, Effective SNR, and EVM are computed.

3) RST / RSP File Format (Channel Import)

The toolkit expects HDF5-based channel files with a /Links hierarchy. The first link is used by default.

  • /Links/<Link>/Transmitter - Tx antenna metadata
  • /Links/<Link>/Receiver - Rx antenna metadata
  • /Links/<Link>/Waveform - bandwidth, center frequency, sounding counts
  • /Links/<Link>/Channel Characterization/Response - frequency response (real/imag interleaved)
  • /Links/<Link>/Channel Characterization/Time Array - frame time axis
Note: If you typed SRT, this toolkit currently supports the same imported channel structure used by RST/RSP style files in this project.

4.1) Frequency Hopping Mode

  • Enable: Check Frequency Hopping in the parameter panel.
  • Input format: Enter comma-separated GHz values, for example 28.02, 28.08, 28.14.
  • Minimum count: At least 3 frequencies are required.
  • Range rule: Every hop frequency must be strictly inside the imported RSP frequency window: (fc - BW/2, fc + BW/2).
  • Execution rule: Frame 1 uses hop 1, frame 2 uses hop 2, and so on; after the last hop, sequence wraps to hop 1.
  • Plots and logs: Active hop carrier is shown during processing so each frame can be traced to its carrier.
Important: RX RF spectrum axis limits remain locked to the imported RSP center frequency and bandwidth, so frame-to-frame comparisons stay consistent.

5) Output Metrics

  • Instant BER: Bit error ratio for current frame only.
  • Theory BER: Analytical QAM BER estimate under AWGN assumptions using estimated SNR.
  • Average BER: Running average across processed frames for stability.
  • Peak SNR: Peak received RF power against configured broadband noise reference.
  • Effective SNR: Symbol-domain estimate derived from gain-aligned error vector power.
  • EVM (%): RMS error-vector magnitude: 100 * sqrt(Perror/Psignal).

6) RX RF Spectrum Unit Note

RX RF spectrum is displayed as dBm/bin (power per FFT bin), not integrated broadband dBm. The plot includes RBW and expected noise-floor guidance for interpretation.

7) Output Plot Details and Interpretation

PlotWhat It RepresentsUnits / AxesHow to Interpret
Constellation Recovered symbol cloud (RX) overlaid with transmitted symbol points (TX) for the selected frame. X: In-phase (I), Y: Quadrature (Q), normalized symbol space. Tight clusters near ideal points indicate low EVM and low BER. Smearing/rotation/spread indicates noise, residual ISI, phase/frequency error, or imperfect equalization.
RX RF Spectrum (Noisy) Spectrum of the noisy received RF waveform after channel convolution and AWGN injection. X: Frequency (MHz), Y: Power (dBm/bin), title includes RBW. Use this to inspect occupied bandwidth and noise floor. Compare expected floor line with measured floor. Signal peak-to-floor separation gives intuitive SNR trend.
Channel Freq vs Power Magnitude of imported channel transfer response H(f) for selected Tx-Rx and frame. X: Frequency (MHz), Y: Power/Magnitude in dB scale. Deep notches indicate frequency-selective fading. Flat response implies milder selectivity and often easier equalization.
Channel Delay: Time vs Power IFFT-based delay profile derived from channel frequency response (multipath energy vs delay). X: Delay (us), Y: Power in dB scale. Early strong taps indicate dominant LOS/early paths. Long delayed taps indicate multipath spread and potential ISI sensitivity.
Reading plots together: a selective channel (freq notches + long delay spread) generally causes broader constellation clusters, higher EVM, and higher BER unless SNR/equalization margin is sufficient.

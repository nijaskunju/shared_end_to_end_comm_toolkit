End to End Communication Analysis Toolkit - Help

This document explains signal-flow architecture, RST/RSP file interpretation, and theory behind each technical input so users can understand and learn the workflow.

1) Toolkit Architecture

  • Input Channel Model: Frequency response H(f) comes from either an RST/RSP archive or a live STK/RFCM project and is converted to an impulse response h(t) through IFFT-based FIR extraction.
  • Live RFCM Mode: STK Engine loads a VDF/SC project, discovers valid RFCM analysis configurations and links, and computes each selected link response in memory at its configured frame times. No intermediate HDF5 archive is required.
  • Transmit Chain: Bits -> Gray-coded M-QAM mapping -> RRC pulse shaping -> oversampled baseband -> RF upconversion at configured center frequency (or active hopping frequency).
  • Propagation/Channel: RF waveform is convolved with h(t), representing the selected Tx-Rx coupling path from the imported file.
  • Noise Model: Either direct SNR-mode AWGN or physical Tx power plus thermal noise density, receiver noise figure, and selectable equivalent noise bandwidth.
  • Receiver Chain: Channel estimation + deconvolution, timing alignment, RF downconversion, matched filtering, symbol recovery, hard demapping, BER/EVM/SNR/SIR/SINR extraction.
  • Per-frame Analytics: Frequency response, delay profile, RX RF spectrum, and constellation panels are generated and exported as an H.264 MP4 video.

2) Signal Processing Flow (Simple)

2.1) Signal Processing Flow (Detailed)

  1. H(f) extraction: For each frame, the selected Tx-Rx response vector is read from channel file.
  2. FIR synthesis: A finite impulse response is derived from H(f) to obtain time-domain channel memory.
  3. QAM generation: Random bits are mapped to QAM symbols with Gray coding to reduce bit-error sensitivity for nearest-neighbor symbol errors.
  4. Pulse shaping: RRC filtering controls inter-symbol interference and spectral occupancy.
  5. Upconversion: Baseband symbols are shifted to RF using configured carrier frequency, or per-frame hopping carrier when hopping is enabled.
  6. Channel convolution: RF transmit sequence is filtered by h(t), producing received RF signal. When interference sources are enabled, each interferer waveform is upconverted to the same active carrier, power-scaled, convolved with its own channel FIR to the same receive antenna, and summed with the desired received signal.
  7. Noise injection:
    • SNR mode: AWGN level is set by user SNR.
    • Power/Noise mode: transmit power scaling and integrated thermal noise are applied. Integrated noise is $P_N=N_0B_\mathrm{eq}F$.
  8. Channel estimation and equalization: Pilot-assisted LS/Wiener estimate is used for deconvolution/equalization.
  9. Synchronization: Cross-correlation aligns the recovered sequence to transmitted timing.
  10. Downconversion + matched filtering: RF is shifted back to baseband and filtered with RRC before symbol sampling.
  11. Decision and KPIs: Symbols are demapped to bits and BER, theory BER, physical SNR, SIR, SINR, Peak SNR, Effective SNR, and EVM are computed.

3) RST / RSP File Format (Channel Import)

The toolkit expects HDF5-based channel files with a /Links hierarchy. After clicking Load Metadata, all available links are discovered and populated into the Link dropdown. The user can then select any link, and the Transmitter and Receiver antenna dropdowns are automatically updated to reflect the antenna count within that link.

  • /Links/<Link>/Transmitter - Tx antenna metadata
  • /Links/<Link>/Receiver - Rx antenna metadata
  • /Links/<Link>/Waveform - bandwidth, center frequency, sounding counts
  • /Links/<Link>/Channel Characterization/Response - frequency response (real/imag interleaved)
  • /Links/<Link>/Channel Characterization/Time Array - frame time axis
Note: If you typed SRT, this toolkit currently supports the same imported channel structure used by RST/RSP style files in this project.

Live STK / RFCM Project Mode

Select STK/RFCM Project (VDF/SC), browse to the project, and click Load Metadata. The RFCM Analysis list appears immediately before Link. Selecting an analysis reconstructs and repopulates its available links automatically, then updates the antenna controls for the selected link.

This mode requires STK 13.1, STK Engine and RF Channel Modeler licenses, and the agi_stk13 wheel supplied under the STK installation's bin/AgPythonAPI directory. RFCM runs through STK Engine in an isolated broker process and returns frequency-pulse responses frame by frame. The process boundary avoids STK's one-Engine-instance-per-Python-process restriction. A bounded two-frame buffer lets RFCM compute upcoming frames while the toolkit post-processes the current frame.

Enable Scenario Graphics Snapshot is an optional checkbox shown only in RFCM project mode, unchecked by default. When enabled, the toolkit starts a second, visible STK Desktop session alongside the headless RFCM Engine session and uses it to capture the project's saved 3D Graphics view at each processed frame's scenario time. (STK Engine does not auto-create a 3D Graphics scene even when graphics are enabled, so snapshot capture requires an actual Desktop session.) Each snapshot is composited above the existing panels, both in the Output Plot Panel preview and in the saved MP4 video. The Scenario Snapshot Interval control sets the minimum scenario-time gap between Desktop captures; the default is 0.30 seconds, and intermediate video frames reuse the latest image. Set it to zero to capture every analysis frame. This requires a second STK Desktop license seat and a working OpenGL renderer, and a visible STK window will open on your desktop for the duration of the analysis. If the graphics session cannot start, the toolkit shows a warning asking you to close any already-open copy of the project and continues without snapshots; if a later frame capture fails, it logs a warning and disables snapshots for the rest of the run. When this checkbox is left unchecked (the default), the entire analysis remains headless and uses only a single STK license.

4.1) Frequency Hopping Mode

  • Enable: Check Frequency Hopping in the parameter panel.
  • Input format: Enter comma-separated GHz values, for example 28.02, 28.08, 28.14.
  • Minimum count: At least 3 frequencies are required.
  • Range rule: Every hop frequency must be strictly inside the imported RSP frequency window: (fc - BW/2, fc + BW/2).
  • Execution rule: Frame 1 uses hop 1, frame 2 uses hop 2, and so on; after the last hop, sequence wraps to hop 1.
  • Plots and logs: Active hop carrier is shown during processing so each frame can be traced to its carrier.
Important: RX RF spectrum axis limits remain locked to the imported RSP center frequency and bandwidth, so frame-to-frame comparisons stay consistent.
RX RF spectrum convention: The received analytic RF samples are first mixed back to their complex envelope so a carrier above the discrete-time Nyquist frequency cannot wrap to the FFT edges. A shifted FFT is then mapped back around the physical RF center frequency. Power is displayed in dBm per FFT bin at the segment RBW shown in the title (fs divided by the segment length, chosen so each frame yields roughly 37 overlapping segments); the integrated value sums the averaged bins without interpolation onto the RFCM frequency grid.

Interference Sources

For a selected RFCM link, the toolkit identifies other links terminating at the same receiver. Enable any candidate in the Interference Sources table and select its waveform and transmit power. The desired and interfering RFCM channels are computed at the same scenario time and their complex received waveforms are summed before noise, channel estimation, equalization, and decoding.

The status panel reports physical SNR, SIR, and SINR. The constellation and BER therefore show the effect of the configured interference. The current waveform choices are QAM, CW tone, and wideband complex noise. QAM interferers use independently randomized symbols and currently inherit the intended signal's QAM order and timing settings. Every interferer is upconverted to the intended signal's active carrier frequency plus the row's Offset (MHz); the offset must lie within ±fs/2 of the carrier, where fs = symbol rate × samples/symbol. Interferers are continuous over the entire received record and pass through their channel in steady state, so a CW tone appears as a single spectral line with a random phase relative to the intended signal. With zero offset, a CW tone collapses to a constant shift of the whole constellation; with a small nonzero offset, each constellation point traces a ring; with an offset beyond the RRC passband, ±(1+β)Rs/2, the matched filter largely rejects it. When frequency hopping is enabled, interferers follow the same per-frame hop, which models a worst-case follower jammer or co-channel user.

5) Output Metrics

  • Instant BER: Bit error ratio for current frame only.
  • Theory BER: Analytical QAM BER estimate under AWGN assumptions using estimated SNR.
  • Average BER: Running average across processed frames for stability.
  • Peak SNR: Peak received RF power against configured broadband noise reference.
  • Post-EQ SNR: Symbol-domain estimate derived from gain-aligned error vector power after channel estimation and equalization. It is not the same quantity as the physical SINR reported below; it reflects whatever interference/noise leaked through equalization.
  • EVM (%): RMS error-vector magnitude: 100 * sqrt(Perror/Psignal).

6) RX RF Spectrum Unit Note

RX RF spectrum is displayed as dBm/bin (power per FFT bin), not integrated broadband dBm. The plot includes RBW and expected noise-floor guidance for interpretation.

7) Output Plot Details and Interpretation

PlotWhat It RepresentsUnits / AxesHow to Interpret
Constellation Recovered symbol cloud (RX) overlaid with transmitted symbol points (TX) for the selected frame. X: In-phase (I), Y: Quadrature (Q), normalized symbol space. Tight clusters near ideal points indicate low EVM and low BER. Smearing/rotation/spread indicates noise, residual ISI, phase/frequency error, or imperfect equalization.
RX RF Spectrum (Persistence) Persistence (density) spectrum of the noisy received RF waveform after channel convolution, interference, and AWGN. The frame is split into Hamming-windowed segments with 75% overlap; color shows how often each frequency/power cell is hit across segments (red/yellow = frequent, blue/purple = rare, black = never). The white trace is the segment-averaged (Welch) spectrum. X: Frequency (MHz), Y: Power (dBm/bin) from −160 to −60, title includes the segment RBW. Use this to inspect occupied bandwidth, noise floor, and how steady each component is. A CW tone is a narrow, consistently colored spike; noise and modulated signals spread vertically across several dB. Signal peak-to-floor separation gives an intuitive SNR trend.
Channel Freq vs Power Magnitude of imported channel transfer response H(f) for selected Tx-Rx and frame. X: Frequency (MHz), Y: Power/Magnitude in dB scale. Deep notches indicate frequency-selective fading. Flat response implies milder selectivity and often easier equalization.
Channel Delay: Time vs Power IFFT-based delay profile derived from channel frequency response (multipath energy vs delay). X: Delay (us), Y: Power in dB scale. Early strong taps indicate dominant LOS/early paths. Long delayed taps indicate multipath spread and potential ISI sensitivity.
Reading plots together: a selective channel (freq notches + long delay spread) generally causes broader constellation clusters, higher EVM, and higher BER unless SNR/equalization margin is sufficient.

8) Epoch Plot Details and Interpretation

Epoch plots appear in the Epoch Plots tab after analysis finishes. Each plot shows a single metric on the Y-axis against the simulation frame number on the X-axis, covering all frames in the imported channel file.

PlotWhat It RepresentsUnits / AxesHow to Interpret
Average BER vs Frame Cumulative running average of bit-error ratio starting from frame 1. Each point is the mean of all BER values up to and including that frame. X: Frame index, Y: Average BER (log scale). A steadily decreasing or converging curve indicates stable channel conditions. Persistent plateaus or rising trends signal that challenging channel frames are consistently degrading link quality.
EVM (%) vs Frame Per-frame root-mean-square error vector magnitude as a percentage of the mean signal power. X: Frame index, Y: EVM (%). Low, stable EVM indicates robust symbol recovery. Spikes correspond to frames with deep fading or strong multipath. Correlate with the Channel Freq vs Power plot of the same frame to identify frequency-selective causes.
Post-EQ SNR (dB) vs Frame Per-frame symbol-domain SNR computed from gain-aligned error vector power after equalization: 10·log10(P_signal / P_error). X: Frame index, Y: Post-EQ SNR (dB). Higher values indicate better equalization and lower symbol error rate. Troughs align with difficult channel frames or strong interference. Compare with the physical SINR plot to see how much margin equalization recovers versus the raw channel condition.
SINR (dB) vs Frame Per-frame physical signal-to-interference-plus-noise ratio measured directly from signal, interference, and noise powers before equalization. X: Frame index, Y: SINR (dB). Tracks the raw channel and interference condition independent of the receiver's equalization performance. A large gap versus Post-EQ SNR indicates the equalizer is substantially improving (or degrading) the effective link quality.
